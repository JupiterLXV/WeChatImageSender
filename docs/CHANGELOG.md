# 变更记录

## 3.6.3：修复历史同图导致误暂停

- 删除 3.6.2 中“发送前存在同内容图片就暂停”的拦截，重复发送图片可以继续等待上传完成。
- 多候选匹配跟踪最新右侧图片，结合新增消息及本轮上传变化区分历史图；旧图滚动和旧上传圈结束不能替代本次新图确认。
- 保留转圈拦截、至少 1.5 秒连续稳定及名称发送前复查，保留手动点击聊天后“刷新/定位聊天”的流程。
- 新增真实视觉算法配合合成图片的重复发送回归；真实微信发送验证仍由用户完成。

## 3.6.2：图片上传完成后再发名称

- 删除“转圈静止即完成”、弱图片匹配放行以及缓存写入缩短等待的路径；转圈、失败标记和局部动画均阻止继续。
- 新消息必须匹配源图，转圈消失后至少连续稳定 1.5 秒并经过四帧确认；名称提交前再次检查，状态不明时暂停人工核实。
- 使用 DPI 感知的客户区截图和消息区布局识别，排除输入框预览；适应较大缩略图、不同显示缩放及浅色/深色转圈。窗口、布局或截图方式变化时暂停，不回退到整张桌面。
- 粘贴已经尝试后不再切换按键实现重放；旧版未完成的图片确认记录恢复时需要重新核实。
- 发送前已存在同内容图片时，暂停人工核实，避免聊天滚动把旧图当作新图完成；粘贴后按 F8 或切换前台窗口时不再继续按发送键。
- 保留手动进入微信聊天后“刷新/定位聊天”的方式、蓝白界面与 Logo。
- 本次验证为人工样张、模拟窗口和离线演示；真实微信发送验收由用户完成。

## 3.6.1：恢复原版手动定位

- 恢复原版微信窗口定位、图片确认和名称提交算法，保留蓝白界面与 Logo。
- 在微信手动进入聊天后，点击程序“刷新/定位聊天”；读不到昵称时允许使用“当前微信聊天”。
- 后台连接检查只更新状态，不代选联系人；手动刷新遇到后台检查时会排队执行。
- 源码启动脚本优先运行当前 `main.py`，避免启动旧版 EXE。
- 本次仅做代码及离线检查，真实发送验证由用户完成。

## 3.6.0

### 界面与品牌

- 改为蓝白桌面工作台，结合 Windows 7 的层次与 Google 风格的简洁排版，集中展示接收对象、队列与任务进度。
- 收拢高级参数，提供可折叠预览与日志，改善窗口空间使用。
- 新增照片叠层与发送箭头组成的原创 Logo，接入窗口、任务栏与打包资源。
- 后台读取图片预览并缓存缩略图，连接检查与扫描不再占用界面主线程。

### 队列与任务恢复

- 文件名、发送名称排序同步调整实际队列；自定义名称与选中预览跟随文件。
- 已开始任务锁定接收对象、顺序与名称；恢复使用历史记录中的接收对象。
- 发送期间禁止导入与编辑队列，过期扫描结果不覆盖新任务或恢复的任务。
- 新建任务保留已有历史记录；恢复时同步任务的剪贴板、快捷键等选项。
- 耗时仅统计本轮新完成的图片，暂停后停止累计。

### 停止与状态确认

- 新增 Windows 本地 OCR 文字读取回退，优先使用已安装的中文识别语言，截图不上传到云端识别服务；无法识别时继续按未知状态处理。

- 保留工作线程启动前已经发出的停止信号，确认等待可响应停止请求。
- 对已经提交但无法确认结果的步骤保留核实状态，减少异常后盲目重发的风险。
- 关闭窗口时先等待发送线程结束再释放资源。
- 修复后台 COM 作用域对业务异常的错误处理。

### 项目组织

- 模块化源码保持唯一实现；根目录旧脚本名作为兼容启动入口。
- 增加可选独立脚本导出工具，生成文件输出到 `dist/standalone/`。
- 整理开发与使用文档，构建默认输出到 `releases/3.6.0/`，公开示例仅使用人工样张。

### 验证范围

已验证离线回归、模拟发送、界面布局，以及当前电脑微信文件传输助手的两张人工样张与对应名称实发。深色微信、125% 显示缩放下，图片画面匹配通过；名称识别曾暂停，调整本地 OCR 裁切与放大后只读复核通过，人工标记完成，未重发。整批无人干预发送与其他微信环境尚待进一步验证。

Windows 7 是视觉参考，运行与打包面向 Windows 10/11。客户端状态确认不代表接收方已收到或阅读，也不构成所有微信版本兼容或固定发送速度的承诺。
